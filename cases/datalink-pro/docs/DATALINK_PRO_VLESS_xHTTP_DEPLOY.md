## 1. АРХИТЕКТУРА РЕШЕНИЯ

### 1.1 Что мы строим

Цель: запустить VLESS+xHTTP как резервный (а в перспективе — основной) протокол параллельно с существующим AmneziaWG. Пользователь получает два конфига в Telegram-боте и переключается между ними самостоятельно.

### 1.2 Стек компонентов

| Компонент | Назначение | Где крутится |
|---|---|---|
| Xray-core | Движок прокси, обрабатывает VLESS+xHTTP | VPS (через 3x-ui) |
| 3x-ui панель | Веб-интерфейс управления Xray, REST API | VPS, тот же сервер |
| Nginx | Reverse proxy, SSL-терминация, маршрутизация | VPS |
| Cloudflare | CDN — скрывает IP сервера, проксирует трафик | Облако (бесплатно) |
| Certbot | SSL-сертификаты Let's Encrypt для домена | VPS |
| Telegram бот | Выдача конфигов пользователям через 3x-ui API | VPS (Python) |
| ЮKassa | Существующая платёжная интеграция | Без изменений |

### 1.3 Схема прохождения трафика

**Через Cloudflare (рекомендуется):**
```
Клиент → Cloudflare (443/HTTPS) → Nginx на VPS → Xray (VLESS+xHTTP) → Интернет
```

**Прямое подключение (без CDN):**
```
Клиент → Nginx на VPS (443) → Xray (VLESS+xHTTP) → Интернет
```

### 1.4 Почему xHTTP лучше Reality для мобильных и CGNAT

- Reality маскирует TLS-рукопожатие, но НЕ маскирует трафик ПОСЛЕ него
- ТСПУ с февраля 2026 анализирует поведенческие паттерны через ML — видит аномалию внутри Reality-сессии
- xHTTP разделяет трафик на обычные HTTP-транзакции — статистически неотличимо от браузера
- xPaddingBytes нормализует размеры пакетов — ML-классификатор видит "нормальный HTTP"
- Через Cloudflare CDN IP сервера полностью скрыт — блокировка IP не помогает РКН

### 2.1 Инфраструктура

| Открытые порты | 443 TCP, 80 TCP | 443, 80 + порт панели 3x-ui |

### 2.2 Доменное имя — важные детали

Нужен домен, DNS которого управляется через Cloudflare. Рекомендуется субдомен вида:
- vpn.datalink-pro.com (латиница — лучше для Cloudflare)
- Или любой другой субдомен — главное чтобы A-запись указывала на IP сервера

> ⚠️ ПРОБЛЕМА с кириллическим доменом даталинк-про.рф:
> Cloudflare поддерживает IDN-домены, но конфигурация Nginx и certbot требует punycode-форму.
> Punycode: xn----7sbaowmfrljlq.xn--p1ai
> Рекомендуется зарегистрировать отдельный латинский домен для VPN-инфраструктуры —
> это изолирует VPN-сервис от основного сайта и упрощает управление сертификатами.

### 2.3 Выбор SNI-донора (для режима с Reality, если понадобится)

SNI-донор — реальный зарубежный сайт, под который маскируется соединение.

Требования к донору:
- Поддерживает TLS 1.3
- Поддерживает HTTP/2
- НЕ за CDN (не Cloudflare, не Akamai)
- Не заблокирован РКН
- Не перенаправляет на другой домен

Проверить:
```bash
curl -I --tls-max 1.3 https://ДОНОР.com
# Должен вернуть 200 OK без редиректов
```

Хорошие доноры (проверены апрель 2026):
- www.speedtest.net
- speed.cloudflare.com (парадоксально, но работает при прямом подключении)
- cdn.jsdelivr.net
- Актуальный список: github.com/YukiKras/vless-wizard/blob/main/sni.txt

## 3. УСТАНОВКА СЕРВЕРА — ПОШАГОВЫЙ ПЛАН

### 3.1 Шаг 1: Подготовка сервера

```bash
# Подключение к серверу
ssh root@85.137.166.209

# Обновление системы
apt update && apt upgrade -y

# Установка зависимостей
apt install -y curl wget git nginx certbot python3-certbot-nginx ufw

# Настройка файрвола
ufw allow 22/tcp      # SSH
ufw allow 80/tcp      # HTTP (для certbot)
ufw allow 443/tcp     # HTTPS (основной порт клиентов)
ufw allow 54321/tcp   # Порт панели 3x-ui (можно изменить на любой)
ufw enable
```

> ⚠️ ОШИБКА #1: Конфликт с существующим веб-сервером
>
> СИМПТОМ: "Address already in use" при запуске Nginx.
> ПРИЧИНА: Уже запущен datalink_web.py или другой процесс на порту 80/443.
> РЕШЕНИЕ: Определить что занимает порт:
> ```bash
> ss -tlnp | grep ':80\|:443'
> ```
> Остановить конфликтующий процесс или изменить его порт перед установкой Nginx.

### 3.2 Шаг 2: Установка 3x-ui

```bash
# Установка одной командой
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)

# В процессе установки скрипт спросит:
# - Порт панели (ИЗМЕНИТЬ с дефолтного 54321 на нестандартный, например 47821)
# - Имя пользователя администратора
# - Пароль администратора (использовать сложный)

# После установки:
x-ui status          # Проверить статус
x-ui start           # Запустить если не запущен

# Панель доступна по адресу:
# http://85.137.166.209:ВАШ_ПОРТ/
```

> ⚠️ ОШИБКА #2: Панель не открывается после установки
>
> ПРИЧИНА 1: Порт закрыт в UFW.
> РЕШЕНИЕ: ufw allow ВАШ_ПОРТ/tcp && ufw reload
>
> ПРИЧИНА 2: 3x-ui не запустился.
> РЕШЕНИЕ: x-ui start, затем x-ui logs для просмотра ошибок.
>
> ПРИЧИНА 3: Порт занят другим процессом.
> РЕШЕНИЕ: ss -tlnp | grep ВАШ_ПОРТ — найти и остановить конфликт.
>
> ПРИЧИНА 4: SmartApe (хостер) блокирует нестандартные порты.
> РЕШЕНИЕ: Уточнить у хостера или изменить порт панели через x-ui → пункт 14.

### 3.3 Шаг 3: Получение SSL-сертификата

```bash
# СНАЧАЛА убедиться что A-запись в DNS уже указывает на IP сервера
# Проверить:
dig vpn.ваш-домен.com +short
# Должен вернуть: 85.137.166.209

# Получить сертификат
certbot --nginx -d vpn.ваш-домен.com

# Certbot настроит Nginx для HTTP→HTTPS редиректа автоматически
# Сертификаты хранятся в: /etc/letsencrypt/live/vpn.ваш-домен.com/
```

> ⚠️ ОШИБКА #3: Certbot не может получить сертификат
>
> ПРИЧИНА 1: DNS ещё не распространился.
> РЕШЕНИЕ: Ждать 5-15 минут (редко до 24 часов). Проверять через dig.
>
> ПРИЧИНА 2: Порт 80 закрыт.
> РЕШЕНИЕ: ufw allow 80/tcp
>
> ПРИЧИНА 3: Cloudflare включён как прокси (оранжевое облако).
> РЕШЕНИЕ: Временно переключить на серое облако (DNS only), получить сертификат, включить обратно.
>
> ПРИЧИНА 4: Порт 80 занят другим процессом.
> РЕШЕНИЕ: certbot certonly --standalone -d ДОМЕН
> (Nginx должен быть остановлен: systemctl stop nginx)

## 4. НАСТРОЙКА XRAY И СОЗДАНИЕ INBOUND

### 4.1 Создание VLESS+xHTTP inbound в панели

Войти в панель: http://85.137.166.209:ВАШ_ПОРТ → Inbounds → Add Inbound

| Поле | Значение | Комментарий |
|---|---|---|
| Protocol | vless | |
| Port | 12345 (любой свободный) | Внутренний порт Xray, НЕ порт клиента |
| Security | tls | Для xHTTP без Reality |
| Certificate File | /etc/letsencrypt/live/ДОМЕН/fullchain.pem | Путь к сертификату certbot |
| Key File | /etc/letsencrypt/live/ДОМЕН/privkey.pem | Путь к ключу certbot |
| Transport | xhttp | Выбрать из выпадающего списка |
| Mode (xHTTP) | packet-up | Наиболее совместимый с Cloudflare CDN |
| Path | /vless-xhttp (любой путь) | Должен совпадать с Nginx конфигом |
| Sniffing | Включить | ОБЯЗАТЕЛЬНО для split-tunneling |
| Flow | Не выбирать / пусто | Flow только для Reality+TCP, здесь не нужен |

> ⚠️ ОШИБКА #4: xHTTP не отображается в списке транспортов
>
> ПРИЧИНА: Устаревшая версия 3x-ui (xHTTP добавлен в новых версиях).
> РЕШЕНИЕ: Обновить 3x-ui командой: x-ui update
> Затем проверить в панели: Settings → Xray Version должна быть 25.x+

> ⚠️ ОШИБКА #5: Клиент подключается но трафик не идёт
>
> ПРИЧИНА 1: Sniffing выключен — включить в настройках inbound.
>
> ПРИЧИНА 2: Routing не настроен.
> РЕШЕНИЕ: В 3x-ui → Routing добавить правила (см. раздел 4.2).
>
> ПРИЧИНА 3: DNS leak — проверить через dnsleaktest.com с включённым VPN.
>
> ПРИЧИНА 4: Неверный Path в клиенте — должен совпадать с настройкой inbound в 3x-ui.

### 4.2 Настройка раздельной маршрутизации (Split Tunneling)

КРИТИЧЕСКИ важно для пользователей в РФ — российские сайты (банки, Wildberries, Ozon, Госуслуги) должны открываться напрямую, иначе они блокируют VPN-трафик.

В панели 3x-ui → Routing → Add Rules:

| Условие | Действие |
|---|---|
| geoip:ru (российские IP) | direct (напрямую, без VPN) |
| geosite:ru (российские домены) | direct |
| geosite:category-ads-all | block (опционально, блокировка рекламы) |
| Всё остальное | proxy (через VPN) |

## 5. НАСТРОЙКА NGINX И CLOUDFLARE

### 5.1 Конфигурация Nginx как reverse proxy

Создать файл: /etc/nginx/sites-available/vless-xhttp

```nginx
server {
    listen 443 ssl http2;
    server_name vpn.ваш-домен.com;

    ssl_certificate /etc/letsencrypt/live/vpn.ваш-домен.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/vpn.ваш-домен.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;

    # Маршрут для xHTTP-трафика
    location /vless-xhttp {
        proxy_pass http://127.0.0.1:12345;  # Порт Xray inbound из шага 4.1
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 315s;
        proxy_send_timeout 315s;
        proxy_buffering off;
    }

    # Заглушка — реальный сайт для маскировки (при сканировании извне видно обычный сайт)
    location / {
        return 200 'OK';
        add_header Content-Type text/plain;
    }
}

# HTTP -> HTTPS редирект
server {
    listen 80;
    server_name vpn.ваш-домен.com;
    return 301 https://$server_name$request_uri;
}
```

```bash
# Активировать конфиг и проверить
ln -s /etc/nginx/sites-available/vless-xhttp /etc/nginx/sites-enabled/
nginx -t              # ОБЯЗАТЕЛЬНО проверить синтаксис перед перезапуском
systemctl reload nginx
```

> ⚠️ ОШИБКА #6: nginx -t выдаёт ошибку
>
> СИМПТОМ: "could not build server_names_hash..."
> РЕШЕНИЕ: В /etc/nginx/nginx.conf найти секцию http{} и добавить:
> server_names_hash_bucket_size 128;
>
> СИМПТОМ: "No such file or directory" для сертификатов
> РЕШЕНИЕ: Проверить пути: ls -la /etc/letsencrypt/live/ВАШ-ДОМЕН/
> Если папки нет — certbot ещё не выпустил сертификат (вернуться к шагу 3.3).
>
> СИМПТОМ: Синтаксическая ошибка в конфиге
> РЕШЕНИЕ: Проверить что все кавычки и скобки закрыты, точки с запятой на месте.

### 5.2 Настройка Cloudflare

| Действие | Где в интерфейсе CF | Значение |
|---|---|---|
| Добавить домен | cloudflare.com → Add Site | Ваш домен |
| Создать A-запись | DNS → Add Record | Name: vpn, Content: 85.137.166.209 |
| Режим прокси | DNS, иконка облака рядом с записью | Оранжевое облако (Proxied) — ОБЯЗАТЕЛЬНО |
| SSL/TLS режим | SSL/TLS → Overview | Full (strict) |
| HTTP/2 | Speed → Optimization | Включить |
| WebSockets | Network | Включить |
| gRPC | Network | Включить |
| Minimum TLS | SSL/TLS → Edge Certificates | TLS 1.2 |

> ⚠️ ОШИБКА #7: Cloudflare возвращает ошибку 502/503
>
> ПРИЧИНА 1: Nginx не запущен или упал.
> ПРОВЕРИТЬ: systemctl status nginx
>
> ПРИЧИНА 2: Xray не запущен.
> ПРОВЕРИТЬ: x-ui status
>
> ПРИЧИНА 3: SSL/TLS режим Cloudflare не совпадает с сервером.
> - Если на сервере самоподписанный сертификат: режим "Full" (не strict).
> - Если Let's Encrypt: режим "Full (strict)".
>
> ПРИЧИНА 4: Cloudflare не пропускает специфичные HTTP-заголовки xHTTP.
> РЕШЕНИЕ: Cloudflare → Transform Rules → создать правило пропуска проверки заголовков.

> ⚠️ ОШИБКА #8: Работает без Cloudflare, не работает через CF
>
> ПРИЧИНА 1: Используется нестандартный порт. Cloudflare Free проксирует ТОЛЬКО: 80, 443, 8080, 8443, 8888 и ряд других. Убедиться что клиент подключается на 443.
>
> ПРИЧИНА 2: Режим xHTTP не packet-up. Режимы stream-up и stream-one требуют дополнительной настройки для работы через CF.
> РЕШЕНИЕ: В inbound переключить Mode на packet-up.
>
> ПРИЧИНА 3: WebSockets или gRPC не включены в настройках CF (см. таблицу выше).

Базовый URL API: http://127.0.0.1:ВАШ_ПОРТ (использовать localhost, не внешний IP)

> РЕШЕНИЕ: Использовать http://127.0.0.1:PORT, а не внешний IP.
>
> ПРИЧИНА 4: Панель 3x-ui упала или перезапустилась.
> РЕШЕНИЕ: x-ui start, затем проверить x-ui status.

### 6.4 Формат VLESS-ссылки для пользователя

После создания клиента в 3x-ui формируется ссылка:

```
vless://UUID@vpn.ваш-домен.com:443?type=xhttp&security=tls&path=%2Fvless-xhttp#DataLink-PRO

# Расшифровка:
# UUID        — уникальный ID пользователя (UUID v4, генерируется автоматически)
# type=xhttp  — транспорт xHTTP
# security=tls — TLS шифрование
# path        — /vless-xhttp (должен совпадать с Nginx и inbound)
# #DataLink-PRO — название соединения (отображается в приложении клиента)
```

Ссылку можно передавать как текст или как QR-код (панель 3x-ui генерирует QR автоматически).

## 8. МОНИТОРИНГ И ОБСЛУЖИВАНИЕ

### 8.1 Обязательный мониторинг

| Инструмент | Что мониторит | Настройка |
|---|---|---|
| UptimeRobot (бесплатно) | Доступность HTTPS эндпоинта каждые 5 мин | Уведомление в Telegram |
| Логи 3x-ui | Подключения, ошибки Xray | x-ui logs -f |
| Логи Nginx | HTTP-ошибки, 502/503 | tail -f /var/log/nginx/error.log |
| Disk space | Переполнение диска (логи растут) | df -h + cron-alert |

Настроить UptimeRobot на URL: https://vpn.ваш-домен.com — он должен возвращать 200 OK.

### 8.2 Критические команды

```bash
# Статус всех сервисов одной командой
x-ui status && systemctl status nginx

# Перезапуск Xray (без перезапуска панели)
x-ui restart

# Обновление 3x-ui (ОСТОРОЖНО — может изменить версию Xray)
x-ui update

# Проверить текущую версию Xray
x-ui version

# Логи Xray в реальном времени
x-ui logs -f

# Логи Nginx
tail -100 /var/log/nginx/error.log

# Проверить сертификат (дата истечения)
certbot certificates

# Принудительное обновление сертификата
certbot renew --force-renewal

# Проверить IP сервера (не изменился ли)
curl ifconfig.me

# Проверить что нужные порты открыты
ss -tlnp | grep ':443\|:80'

# Посмотреть активные подключения через Xray
x-ui logs -f | grep "accepted"
```

### 8.3 Алгоритм действий при массовом отвале пользователей

```
1. Проверить статус: x-ui status && systemctl status nginx
2. Проверить внешнюю доступность: curl https://vpn.ваш-домен.com
3. Проверить Cloudflare статус: cloudflarestatus.com
4. Посмотреть логи: x-ui logs -f (последние 50 строк)
5. Проверить не изменился ли IP сервера: curl ifconfig.me
   → Если изменился: обновить A-запись в Cloudflare DNS
6. Если проблема в ТСПУ (новая волна блокировок):
   → Сменить SNI-донор в настройках inbound
   → Или сменить Path (/vless-xhttp на другой)
7. Если ничего не помогает — временно переключить пользователей на AWG
```

> ⚠️ ОШИБКА #10: После обновления 3x-ui пользователи перестали подключаться
>
> ПРИЧИНА: Версия Xray-core изменилась — старые клиентские приложения несовместимы.
> СИМПТОМ: В логах xray ошибки версии протокола или handshake failed.
>
> РЕШЕНИЕ:
> 1. Проверить версию: x-ui version
> 2. Уведомить пользователей обновить приложение до последней версии
> 3. Если нужен откат — переустановить конкретную версию 3x-ui:
>    bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh) ВЕРСИЯ
>
> ПРОФИЛАКТИКА: Тестировать обновления на одном тестовом аккаунте
> перед применением на всех пользователей.

Шаг 2. Установить 3x-ui на существующий сервер (раздел 3.2).

Шаг 4. Создать VLESS+xHTTP inbound в панели (раздел 4.1).

Шаг 5. Настроить Nginx reverse proxy (раздел 5.1).

Шаг 6. ТЕСТ — подключиться самому с Android и iOS, проверить YouTube,
        проверить что Яндекс открывается напрямую (split tunneling).

Шаг 7. Интегрировать 3x-ui API в бота (или поднять готовый бот, раздел 6.2).

Шаг 8. Beta-запуск — новым пользователям выдавать ОБА конфига (AWG + VLESS).

Шаг 9. Параллельно мигрировать существующих пользователей с AWG Legacy на AWG 2.0

### 9.3 Что НЕ делать

- НЕ удалять AWG до подтверждения стабильности VLESS — иметь откат
- НЕ обновлять Xray-core без уведомления пользователей
- НЕ использовать один домен для VPN-трафика и основного сайта
- НЕ хранить credentials 3x-ui в репозитории — только в .env файлах
- НЕ запускать панель 3x-ui на публичном порту без надёжного пароля
- НЕ выкладывать vless:// ссылки публично — каждый пользователь получает уникальный UUID

## 10. СВОДНАЯ ТАБЛИЦА ОШИБОК И РЕШЕНИЙ

| # | Симптом | Причина | Решение |
|---|---|---|---|
| #1 | "Address already in use" при Nginx | Конфликт на порту 80/443 | ss -tlnp \| grep ':80\|:443' → остановить конфликт |
| #2 | Панель 3x-ui не открывается | Порт закрыт или сервис не запущен | ufw allow PORT → x-ui start → проверить хостера |
| #3 | Certbot не получает сертификат | DNS не распространился, порт 80 закрыт, CF прокси | Ждать DNS, открыть 80, отключить CF-прокси на время |
| #4 | xHTTP нет в списке транспортов | Устаревшая версия 3x-ui | x-ui update |
| #5 | Подключён но трафик не идёт | Sniffing выключен, нет routing, неверный path | Включить Sniffing, настроить routing, проверить path |
| #6 | nginx -t ошибка | Неверные пути сертификатов, hash_bucket | Проверить пути, добавить server_names_hash_bucket_size 128 |
| #7 | Cloudflare 502/503 | Nginx/Xray не работают, неверный SSL mode | Проверить сервисы, установить Full (strict) в CF |
| #8 | Работает без CF, не работает с CF | Нестандартный порт, неверный режим xHTTP | Использовать порт 443, режим packet-up |
| #9 | Бот не авторизуется в 3x-ui API | Неверные credentials, истекла сессия, внешний IP | Проверить .env, авторереавторизация, использовать 127.0.0.1 |
| #10 | После обновления пользователи отвалились | Несовместимость версий Xray клиент/сервер | Уведомить обновить приложение, проверить x-ui version |

## 11. КОНТРОЛЬНЫЙ ЧЕКЛИСТ ПЕРЕД ЗАПУСКОМ

Перед тем как открыть доступ пользователям — пройти все пункты:

```
СЕРВЕР И СЕТЬ
[ ] Сервер обновлён (apt upgrade -y)
[ ] UFW настроен: открыты 22, 80, 443, порт панели
[ ] 3x-ui установлен и запущен (x-ui status = running)
[ ] Версия Xray в 3x-ui: 25.x+ (x-ui version)

ДОМЕН И SSL
[ ] Домен настроен в Cloudflare (A-запись + оранжевое облако)
[ ] SSL/TLS режим Cloudflare: Full (strict)
[ ] WebSockets и gRPC включены в Cloudflare
[ ] SSL-сертификат получен через certbot (не истечёт раньше чем через 60 дней)

NGINX И XRAY
[ ] Nginx настроен и перезапущен без ошибок (nginx -t OK)
[ ] VLESS+xHTTP inbound создан в панели (Mode: packet-up)
[ ] Sniffing включён
[ ] Routing настроен: geoip:ru → direct, остальное → proxy

ТЕСТИРОВАНИЕ
[ ] Тестовый клиент подключился с Android (v2RayTun)
[ ] Тестовый клиент подключился с iOS (v2RayTun через смену региона)
[ ] YouTube открывается через VPN (скорость приемлемая)
[ ] Яндекс.ru открывается напрямую, без VPN-IP (split tunneling работает)
[ ] Проверить dnsleaktest.com — DNS не утекает

БОТ И МОНИТОРИНГ
[ ] Бот выдаёт VLESS-ссылку при запросе конфига
[ ] Один экземпляр бота (нет конфликта 409)
[ ] Бот переведён на systemd с Restart=always
[ ] UptimeRobot настроен на https://vpn.ваш-домен.com → уведомление в Telegram

СОВМЕСТИМОСТЬ С AWG
[ ] Существующий AWG (amnezia-awg2) продолжает работать
[ ] Наталья (native awg0) продолжает работать
[ ] Новые пользователи получают ОБА конфига (AWG + VLESS)
```
