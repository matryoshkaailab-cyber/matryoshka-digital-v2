**2. ПОДХОД — ДА, СОГЛАСЕН**

Минимальный patch — правильное решение. Проблема не в архитектуре filewatcher, а в том что `hermes -p alf chat` — чёрный ящик:

```
subprocess.run → hermes agent → openai.OpenAI(...) — теряет extra_body
```

Меняем на прямой вызов — получаем:
- `temperature=1` (Олег)
- `top_p=0.95`
- `max_tokens=16384`
- `extra_body={"enable_thinking": True, "reasoning_budget": 16384}`

Совместимость: у тебя уже есть `NVIDIA_API_KEY` в `/root/.hermes/profiles/alf/.env`, `openai` пакет есть в venv.

Единственное уточнение: модель **nvidia/llama-3.1-nemotron-70b-instruct** — она точно поддерживает `reasoning_budget`? Проверь: если нет, параметр будет silently ignored (NVIDIA API так делает). Лучше `enable_thinking` только если модель его реально поддерживает.

**3. EDGE CASES — ЧТО МОЖЕШЬ УПУСТИТЬ**

| Edge case | Решение |
|---|---|
| **Rate limit (429)** | `tenacity.retry(stop=stop_after_attempt(3), wait=wait_exponential(min=2, max=30))` — уже есть в xai_filewatcher |
| **Timeout (30s по умолчанию)** | `httpx.Client(timeout=httpx.Timeout(120.0, connect=10.0))` — длинные reasoning ответы могут идти >60s |
| **NVIDIA API 503/5xx** | `retry_if_exception(lambda e: isinstance(e, (APIError, APITimeoutError, RateLimitError)))` |
| **WAL append race** | `filelock` на `.wal` — уже есть |
| **Переменная окружения не загружена** | `os.environ.get('NVIDIA_API_KEY')` + raise если None — иначе `openai.OpenAI()` упадёт с неинформативной ошибкой |
| **Streaming vs non-streaming** | `stream=False` + `.choices[0].message.content` — без стриминга, проще и стабильнее |
| **Unicode в ответе (Cyrillic/emojis)** | NVIDIA API возвращает UTF-8, но `subprocess` иногда ломает кодировку — при прямом API этой проблемы нет |
| **Длинный ответ (>16K токенов)** | `max_tokens=16384` + `finish_reason != "length"` проверка; если обрезан — логировать в WAL с `TRUNCATED` флагом |
| **WAL append перед .sent** | Сначала WAL, потом `.sent` — atomic rename — уже есть |

**Что ты не упомянул, но нужно:**
- **Healthcheck**: если API упал, filewatcher не должен удалять .wal (сейчас `alf_filewatcher.py` удаляет даже при ошибке — баг)
- **Model fallback**: если основная модель 5xx, retry на запасную (через `tenacity` + список моделей)

**5. РИСКИ И FAILOVER**

| Риск | Вероятность | Действие |
|---|---|---|
| **NVIDIA API 429** (rate limit) | Medium | `tenacity` retry 3x, exponential backoff (2-30s). Если всё ещё 429 — sleep 60s, retry 1x. Если нет — WAL не трогать, оставить для следующего цикла |
| **NVIDIA API 503** (overloaded) | Low-Medium | retry 3x. Если не ок — fallback на `hermes -p alf chat -q` (старый путь) |
| **NVIDIA API 5xx** | Low | retry 3x → fallback на старый subprocess |
| **API key revoked/expired** | Low | `AuthenticationError` → логировать в WAL с `AUTH_FAILED`, не удалять .wal, алерт в Telegram |
| **Модель deprecated/renamed** | Low | `NotFoundError` → retry с запасной моделью из списка |
| **Network partition** | Low | `APIConnectionError` → retry 3x → fallback |
| **Длинный ответ + reasoning = >2 мин** | Medium | Увеличить `httpx.Timeout` до 180s. Если timeout — retry 1x с `stream=True` (fallback streaming) |
| **Filewatcher crash во время API call** | Low | WAL уже записан до вызова → при перезапуске retry orphaned WAL |
| **Memory leak (резидентный процесс)** | Low | `call_alf()` создаёт `openai.OpenAI()` каждый раз → не страшно, но лучше создать `ClientSession` один раз и переиспользовать |

**Главный риск:** NVIDIA API не поддерживает `reasoning_budget` для этой модели. Тогда параметр будет ignored, и Альф не получит режим reasoning. **Проверь** через тест #2: если ответ содержит "I am an AI" без reasoning_depth, значит не поддерживает. Тогда `enable_thinking=False`.

**ГОТОВЫЙ КОД** — минимальный patch для `call_alf()`:

```python
import os
import httpx
import openai
from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type
from openai import APIError, APITimeoutError, RateLimitError

def _make_alf_client() -> openai.OpenAI:
    api_key = os.environ.get('NVIDIA_API_KEY')
    if not api_key:
        raise ValueError("NVIDIA_API_KEY not set")
    return openai.OpenAI(
        base_url="https://integrate.api.nvidia.com/v1",
        api_key=api_key,
        http_client=httpx.Client(timeout=httpx.Timeout(180.0, connect=10.0))
    )

@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=2, min=2, max=30),
    retry=retry_if_exception_type((APIError, APITimeoutError, RateLimitError)),
    reraise=True
)
def _alf_chat(client: openai.OpenAI, question: str) -> str:
    resp = client.chat.completions.create(
        model="nvidia/llama-3.1-nemotron-70b-instruct",
        messages=[{"role": "user", "content": question}],
        temperature=1,
        top_p=0.95,
        max_tokens=16384,
        extra_body={"enable_thinking": True, "reasoning_budget": 16384}
    )
    return resp.choices[0].message.content

def call_alf(question: str) -> str:
    client = _make_alf_client()
    return _alf_chat(client, question)
```

Весь остальной код `alf_filewatcher.py` (WAL, `.sent`, lock) не трогать — меняется только `call_alf()`.

**Итого:** подход верный, риски покрываем retry + fallback, тесты напиши до деплоя. Если что-то из этого уже сделано — сорри за дубляж, пиши по памяти как есть.
