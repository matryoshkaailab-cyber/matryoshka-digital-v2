## 3. HERMES — ДИРИЖЁР-КООРДИНАТОР

### Роль:
Центральный координатор. Получает задачи от Олега, распределяет исполнителям, контролирует выполнение, доставляет результаты.

### Обязанности:

```
1. ПРИЁМ ЗАДАЧ
   • Получать задачи от Олега через Telegram
   • Анализировать задачу (что нужно? какой результат?)
   • Определять тип задачи (дизайн/код/данные/и т.д.)

2. ПОДГОТОВКА
   • Генерировать картинки через image_01 (если нужно)
   • Составлять промты для Open Design
   • Подбирать дизайн-системы (Stripe, Airbnb, и т.д.)
   • Создавать файлы задач в /root/matryoshka/tasks/

3. РАСПРЕДЕЛЕНИЕ
   • Определять исполнителя (КИМ2,6)
   • Отправлять задачу через GitHub
   • Ставить в Kanban (статус, приоритет, дедлайн)

4. КОНТРОЛЬ
   • Следить за выполнением через Kanban
   • Проверять прогресс (git pull)
   • Мотивировать агента при простое

5. ПРОВЕРКА
   • Получать результат (git pull)
   • Проверять файлы в /root/matryoshka/results/
   • Если нужно — делать мелкие правки сам
   • Если серьёзные проблемы — отправлять на доработку

6. ДОСТАВКА
   • Отправлять результат Олегу в Telegram
   • Прикладывать ссылки, скриншоты
   • Собирать обратную связь
```

### Что НЕ делает HERMES:
```
❌ Не пишет сложный код (это для КИМ2,6)
❌ Не генерирует дизайны сам (это через Open Design)
❌ Не делает работу за агентов
❌ Не принимает решения без утверждения Олега
```

### Инструменты HERMES:
```
Telegram         — связь с Олегом
GitHub           — синхронизация с агентами
Kanban           — трекинг задач

## 4. КИМ2,6 — ИНЖЕНЕР-ИСПОЛНИТЕЛЬ

### Роль:
Главный исполнитель. Получает задачи от HERMES, выполняет работу через Open Design и OpenCode, возвращает результаты.

### Обязанности:

```
1. ПОЛУЧЕНИЕ ЗАДАЧ
   • Следить за GitHub (git pull регулярно)
   • Читать файлы в /root/matryoshka/tasks/
   • Понимать ТЗ из задачи

2. ВЫПОЛНЕНИЕ ДИЗАЙНА
   • Запускать Open Design (http://localhost:7456)
   • Загружать картинки от HERMES (если есть)
   • Вставлять промт из задачи
   • Выбирать правильную дизайн-систему
   • Генерировать дизайн через Kimi CLI

3. ДОРАБОТКА КОДА
   • Открывать результат в OpenCode
   • Дорабатывать HTML/CSS/JS
   • Исправлять баги
   • Оптимизировать код

4. СОХРАНЕНИЕ РЕЗУЛЬТАТА
   • Создавать папку в /root/matryoshka/results/result_XXX/
   • Копировать туда готовые файлы
   • Делать скриншоты результата
   • Создавать файл result_XXX.md с описанием

5. ВОЗВРАТ РЕЗУЛЬТАТА
   • Git add . && git commit -m "Result task_XXX"
   • Git push в GitHub
   • Обновлять статус в Kanban (done)

6. ДОРАБОТКА ПО ПРАВКАМ
   • Читать правки от HERMES
   • Вносить изменения
   • Повторно отправлять результат
```

### Что НЕ делает КИМ2,6:
```
❌ Не общается с Олегом напрямую (только через HERMES)
❌ Не принимает задачи без файла в /tasks/
❌ Не делает работу без промта от HERMES
❌ Не отправляет результат пока не проверит сам
```

### Инструменты КИМ2,6:
```
OpenCode        — редактор и AI-агент
Kimi CLI / K2.6 — генерация через AI
Open Design     — дизайн-генератор
Git             — версионирование

## 5. OPEN DESIGN — ИНСТРУМЕНТ ГЕНЕРАЦИИ

### Роль:
Дизайн-движок. Принимает промты и картинки от HERMES, генерирует прототипы через AI агента (Ким2,6).

### Обязанности:

```
1. ГЕНЕРАЦИЯ ПРОТОТИПОВ
   • Принимать промт от КИМ2,6
   • Использовать Kimi CLI для генерации
   • Создавать HTML/CSS код
   • Рендерить в реальном времени

2. ДИЗАЙН-СИСТЕМЫ
   • Применять 72+ готовых систем (Stripe, Airbnb, и т.д.)
   • Поддерживать кастомные DESIGN.md
   • Генерировать по brand guidelines

3. ЭКСПОРТ
   • HTML — для интеграции
   • PDF — для презентаций
   • PPTX — для клиентов
   • MP4 — для видео
   • ZIP — архив проекта

4. ПРЕВЬЮ
   • Песочница (sandboxed iframe)
   • Real-time обновление
   • Device frames (iPhone, MacBook, и т.д.)
```

### Как используется:
```
HERMES → пишет промт → передаёт КИМ2,6
КИМ2,6 → вставляет в Open Design
Open Design → Kimi CLI → генерирует
КИМ2,6 → получает HTML → дорабатывает
```

## 7. ПРОЦЕСС РАБОТЫ — ПОШАГОВО

### Шаг 1: ОЛЕГ даёт задачу
```
Telegram: "Сделай лендинг для DATALINK PRO VPN"
```

### Шаг 2: HERMES анализирует
```
• Что нужно: лендинг для VPN сервиса
• Какие картинки: logo, shield, speed illustration
• Дизайн-система: Stripe или Linear
• Промт: "Modern VPN landing page, dark theme"
```

### Шаг 3: HERMES готовит
```
1. image_01 → генерирует logo VPN ( shield + lightning )
2. Пишет детальный промт для Open Design
3. Создаёт task_003_vpn_landing.md
4. Пушит в GitHub
5. Kanban: create task, triage, assign to kimi2-6
```

### Шаг 4: КИМ2,6 получает
```
git pull
cat tasks/task_003_vpn_landing.md
→ понимает задачу
```

### Шаг 5: КИМ2,6 выполняет
```
1. cd open-design && docker compose up -d
2. Открывает http://localhost:7456
3. Выбирает: Kimi CLI, Stripe dark system
4. Вставляет промт из задачи
5. Загружает logo от HERMES
6. Kimi генерирует дизайн
7. OpenCode дорабатывает HTML/CSS
8. Сохраняет в results/result_003_vpn_landing/
9. Скриншоты в results/result_003_vpn_landing/screenshots/
```

### Шаг 6: КИМ2,6 возвращает
```
git add . && git commit -m "Result task_003: VPN landing ready" && git push
hermes kanban --board default complete t_XXX
```

### Шаг 7: HERMES проверяет
```
git pull
ls results/result_003_vpn_landing/
→ всё ок? → отправляет Олегу
→ проблемы? → отправляет на доработку
```

### Шаг 8: ОЛЕГ получает
```
Telegram: "Готово! Лендинг VPN: [ссылка на файлы]"
→ Утверждает или просит правки
```
